# YALauncher

**Yet another launcher.** Один exe в трее: по <kbd>Ctrl</kbd>+<kbd>Alt</kbd>+<kbd>Space</kbd> посреди того монитора, где стоит курсор, появляется строка поиска, в которой за пару нажатий находится и запускается любая программа.

Никаких .NET, Avalonia, CGO и зависимостей: чистый Win32 через `syscall`, ~6 МБ exe и ~50 МБ памяти.

---

## Зачем

Flow Launcher — хорошая штука, но это WPF-приложение на .NET: холодный старт — секунды, в памяти — сотни мегабайт, а окно рисуется за 100–300 мс. YALauncher берёт из него лучшие идеи — индексацию Стартового меню и `App Paths`, тот же алгоритм нечёткого поиска, тот же набор горячих клавиш — и отбрасывает всё остальное:

| | Flow Launcher 2.0 | YALauncher |
| --- | --- | --- |
| Стек | .NET 9 + WPF | Go + Win32, без зависимостей |
| Размер | ~200 МБ каталог | один exe ~6 МБ |
| Память | ~300 МБ | ~50 МБ |
| Окно поиска | WPF, анимация | GDI, рисуется сразу |
| Индекс | ~277 программ | 276 программ, ~55 мс (из кэша — 0 мс) |

## Что умеет

- **Хоткей из любого места.** <kbd>Ctrl</kbd>+<kbd>Alt</kbd>+<kbd>Space</kbd> открывает окно на мониторе под курсором (не на главном). Хоткей меняется в конфиге, `Esc` закрывает.
- **Нечёткий поиск как в Flow Launcher.** `chr` → Chrome, `vs19` → Visual Studio 2019, `gc` → Google Chrome (акронимы), кириллица тоже работает. Точность — `loose` / `regular` / `strict`.
- **Индексирует то же, что и Flow Launcher**:
  - два Стартовых меню (`%ProgramData%\Microsoft\Windows\Start Menu` и `%APPDATA%\...`);
  - ключи реестра `App Paths` (HKCU и HKLM) — там регистрируются exe всех установщиков;
  - любые папки из конфига (по умолчанию список пуст — под `D:\YandexDisk\Tools` можно добавить свою).
- **`.exe` и `.lnk`** (плюс `.url` и ClickOnce `.appref-ms`). Ярлыки разбираются своим парсером Shell Link: из них берётся и путь к exe, и аргументы, и рабочая папка, чтобы запускать так, как задумал установщик.
- **Мгновенный отклик.** Индекс хранится в `%APPDATA%\YALauncher\index.json` и загружается при старте, поэтому список на экране за доли секунды после запуска. Переиндексация идёт в фоне и подхватывает новые exe по уведомлениям файловой системы (плюс страховка по таймеру — раз в 30 минут).
- **Узнаёт привычки.** Часто запускаемые программы поднимаются выше: `ch` сначала даст Chrome, которым вы пользуетесь каждый день, а не «Chess» из Стартового меню.
- **Калькулятор прямо в строке.** `2^10+1`, `sqrt(16)`, `100500/3` — результат появляется первой строкой, <kbd>Enter</kbd> копирует его в буфер.
- **Иконки настоящие**, тянет их оболочка Windows (`SHGetFileInfo`), то есть как в Проводнике: `.lnk`, UWP-стабы и exe с встроенной иконкой выглядят правильно.
- **Управление с клавиатуры и мыши.** <kbd>Enter</kbd> — запустить, <kbd>Ctrl</kbd>+<kbd>Enter</kbd> — открыть папку программы, <kbd>Ctrl</kbd>+<kbd>Shift</kbd>+<kbd>Enter</kbd> — запустить от администратора (UAC), <kbd>↑</kbd>/<kbd>↓</kbd>, <kbd>Tab</kbd>, колесо, клик — всё работает.
- **Установщик не нужен**: копия exe + трей. Автозапуск пишется в `HKCU\...\Run`, обновления — с GitHub Releases, как у `YALangSwitcher` и `YASShoter`.

## Установка

1. Скачать `YALauncher.exe` из [Releases](../../releases).
2. Положить в постоянную папку, например `D:\YandexDisk\Tools\YALauncher\` (не в `Temp`: путь прописывается в автозапуск).
3. Запустить. В меню трея включить «Запускать при входе в Windows» (по умолчанию уже включено).
4. Добавить свои папки в индекс: меню трея → «Добавить папку в индекс…».

Если хоткей не срабатывает в приложении, запущенном от администратора, — так устроен Windows: хук клавиатуры непривилегированного процесса не видит ввод в elevated-окна. Для лаунчера это почти никогда не нужно: он запускает программы обычным пользователем, а «от администратора» умеет через <kbd>Ctrl</kbd>+<kbd>Shift</kbd>+<kbd>Enter</kbd>.

## Горячие клавиши

| Клавиша | Действие |
| --- | --- |
| <kbd>Ctrl</kbd>+<kbd>Alt</kbd>+<kbd>Space</kbd> | открыть/закрыть поиск (настраивается) |
| <kbd>Enter</kbd> | запустить выбранную программу / скопировать результат калькулятора |
| <kbd>Ctrl</kbd>+<kbd>Enter</kbd> | открыть папку с программой (выделив файл) |
| <kbd>Ctrl</kbd>+<kbd>Shift</kbd>+<kbd>Enter</kbd> | запустить от администратора |
| <kbd>↑</kbd> <kbd>↓</kbd> <kbd>Tab</kbd> | выбор |
| <kbd>Esc</kbd> | очистить строку, второе нажатие — закрыть |
| <kbd>Ctrl</kbd>+<kbd>Delete</kbd> | очистить строку |

Формат хоткея в конфиге: модификаторы через `+`, последним — клавиша. Примеры: `ctrl+alt+space`, `alt+` `, `win+space`, `ctrl+shift+f1`, `f13`.

## Как это работает

```text
WH_KEYBOARD_LL hook  →  Ctrl+Alt+Space съеден  →  WM_APP показать окно
                                                        ↓
                                          окно на мониторе GetCursorPos()
                                                        ↓
                   ввод → линейный проход по индексу (276 записей) → поиск
                                                        ↓
                                ShellExecute / show in folder / runas
```

- **Хук клавиатуры вместо `RegisterHotKey`.** `RegisterHotKey` конфликтует с другими приложениями и не даёт съесть клавишу; низкоуровневый хук возвращает 1 и клавиша не долетает до окна под лаунчером. Тот же хук, пока окно открыто, **передаёт в него все нажатия** — поэтому ввод работает даже на RDP-сессии или поверх полноэкранного приложения, где окно не может забрать реальный фокус.
- **Своё окно на GDI, а не WPF/HTML.** Эти 700 строк рисования — причина, по которой окно появляется за кадр: ни разметки, ни стилей, ни пересчёта layout.
- **Индекс — снапшот с `atomic.Pointer`.** Поиск читает неизменяемый слайс, переиндексация строит новый и подменяет его одним указателем: окно никогда не ждёт сканера.
- **Парсер `.lnk` без COM.** Формат Shell Link документирован; парсер — 300 строк Go. COM-путь (`IShellLink`) требует инициализации STA на потоке UI и может показать диалог «проблема с ярлыком».
- **Кэш, как у Flow Launcher.** Он тоже хранит список программ на диске и переиндексирует по таймеру; здесь кэш — JSON, а таймер дополнен уведомлениями файловой системы.

## Конфиг

`%APPDATA%\YALauncher\config.json`:

```json
{
  "hotkey": "ctrl+alt+space",
  "folders": ["D:\\YandexDisk\\Tools"],
  "startMenu": true,
  "appPaths": true,
  "envPath": false,
  "recursive": true,
  "precision": "regular",
  "autostart": true,
  "autoUpdate": true,
  "updateCheckHours": 6,
  "reindexMinutes": 30,
  "hideUninstallers": true,
  "history": [],
  "frequent": { "count": {}, "last": {} },
  "rejected": []
}
```

| Поле | Что делает |
| --- | --- |
| `hotkey` | хоткей, формат выше |
| `folders` | папки-источники (рекурсивно) |
| `startMenu` | два Стартовых меню |
| `appPaths` | реестр `App Paths` |
| `envPath` | папки из `PATH` |
| `recursive` | заходить в подпапки `folders` |
| `precision` | `loose` / `regular` / `strict` |
| `reindexMinutes` | страховочная переиндексация |
| `hideUninstallers` | не показывать `unins000.exe`, `Uninstall.lnk` и т.п. |

Журнал: `%APPDATA%\YALauncher\yalauncher.log`. Кэш индекса: `index.json` рядом.

## Сборка

Кросс-компиляция из WSL/Linux, без CGO:

```sh
make build VERSION=0.1.0     # build/YALauncher.exe
make icon                    # перерисовать assets/app.ico
make test                    # go vet, тесты, gofmt
```

Для иконки нужен `go-winres` (`go install github.com/tc-hib/go-winres@latest`), сам exe собирается стандартным `go build`.

## Релизы и CI

`.github/workflows/build.yml` собирает exe на каждый пуш в `main` и публикует GitHub Release. Встроенное автообновление читает `/releases/latest`, скачивает `YALauncher.exe`, подменяет файл и перезапускается.

## Структура

```text
YALauncher/
├── main.go              окно трея, хоткей, сообщения, запуск программ
├── ui.go                окно поиска: GDI, ввод, список результатов
├── config.go            конфиг и его нормализация
├── hotkey.go            разбор «ctrl+alt+space»
├── calc.go              калькулятор в строке поиска
├── clipboard.go         буфер обмена для результата калькулятора
├── install.go           автозапуск через HKCU\...\Run
├── browse.go            выбор папки для индекса
├── update.go            автообновление с GitHub
├── glyph.go             иконки-заглушки
├── log.go               лог
├── internal/
│   ├── win/             тонкие Win32-биндинги (окно, хук, GDI, shell, DPI)
│   ├── search/          нечёткий поиск (порт StringMatcher из Flow Launcher)
│   ├── index/           сканер, парсер .lnk, ранжирование, кэш, watcher
│   └── icon/            иконка приложения, рисуется кодом
└── tools/genicon/       генератор .ico
```

## Ограничения

- Только Windows (Win32 + GDI).
- UWP-приложения (Microsoft Store) не индексируются: их ярлыки ведут в `WindowsApps` со специальными ACL. Start Menu ярлыки Windows 11, которые всё-таки `.lnk`, подхватываются.
- Хук не видит клавиши в окнах с более высокими правами (см. выше).
- Оконный менеджер Windows иногда не даёт программе забрать фокус у своего же foreground-окна; когда это случается, окно выходит наверх, но нажать в строку нужно один раз мышью.
